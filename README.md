# RIME LLM 候选重排（rime-llm-rerank）

## 快速开始（以朙月拼音为例，约 5 分钟）

> 目标：让 **朙月拼音 `luna_pinyin`**（Rime 自带默认方案）用上 LLM 候选重排。换别的方案同理：第 5 步的「编码匹配」按该方案的码长改。

1. **装官方小狼毫** —— 本插件跑在官方 `rime.dll` 上：<https://rime.im/download/>（装完确认能打字）。
2. **双击 `installer\install_plugin.bat`** —— 下载/克隆本仓库后跑它（会自动请求管理员）。
3. **方案接入**：`方案文件` 选 **`luna_pinyin.schema.yaml（程序）`**（带「（程序）」= 小狼毫自带的预装方案；保存时会先复制到用户文件夹再改，原件不动）。
4. **下模型**：`总控` → 模型路径留默认 → 点 **『下载模型』**（约 397 MB，ModelScope，断点续传；中断了再点一次接着下；**下完路径框自动填好**）。
5. **改一个参数**：
   - `触发条件` → `编码匹配` 填 **`.+`** —— 朙月拼音码长 1~6 不等，默认的 `.{4}`（恰 4 码）不会触发。
6. **点『复制文件』**（部署 `rime_llm.dll` + 两个 lua）→ 再点 **『保存并生效』**（写进方案并自动重新部署）。
7. **验证**：**连打两个词**——先打 `nihao` 选「你好」上屏，再打 `shijie`，第二个词起重排生效（候选顺序按上文语义变化）。**光标前没有文字时不重排**：重排至少要 1 个上文 token，刚装好（或空文档、刚切窗口）打第一个词时上文为空，引擎直接按原顺序放行，属预期。想确凿看到"上文来源/内容 + 每个候选的分数"：开 [实时调试窗口](#实时调试窗口)（`debug\open_debug_window.bat`，方案里把 `debug_fusion` 勾上再保存生效）。没生效：托盘小狼毫 → **重新部署**。

后续微调都在同一页：`触发条件`（`编码匹配` 正则；**勾上 `整句模式` 时该项锁定为 `.{2,}`**；`整句模式` 下方的 **`前缀自动确认` 只在整句模式勾选时出现**）与 `推理规模`（上文 token / 候选数 / **CPU 线程——点右边『实测线程数』让本机实测给推荐值**）→ **保存并生效**；模型换位置用 **『浏览…』** 选 `.gguf`（**必须是绝对路径**）。不想要了：点 **『剥离』**（组件行与配置节一起删，自动重新部署），再删安装目录里的 `rime_llm.dll` 与 `%APPDATA%\Rime\lua\` 下两个 lua 即为完全卸载。

---

使用本地部署的小型 LLM 为任意 RIME **四码定长**输入方案（五笔、郑码、仓颉、拼读双拼等）提供打字时的智能候选排序。LLM 与编码方案无关——它只看到最终的中文候选词列表，利用上文的语义把正确词排到候选第一位，减少手动选重。

| 关键指标 | 值 |
|------|------|
| 首选率（10 tok / 5 候选） | **93.4%**（单字 96.8%） |
| 感知延迟 | **~43 ms**（CPU，预解码后） |
| 常驻内存 | ~0.6 GB（模型加载后实测；模型权重 ~397 MB + 推理缓存） |
| 模型 | Qwen3-0.6B **Base** Q4_K_M（397 MB，GGUF，自建上传 ModelScope；2026-11-19 定案——重排与预训练同分布，base 版比对话微调版更准且更快，研究帕累托最优 100ms/3.28%（6 万窗）；前身为 Qwen2.5-0.5B-Instruct） |
| 选重率 | 可降至原方案（字典序）的 **1/3** |
| 依赖 | 零（纯本地 CPU 推理） |

核心手段：**跨熵（CE）评分**而非文本生成——候选 token 全部并行解码，最多 3 次 `llama_decode`，与候选数无关；**预解码**利用 commit 到编码打完的时间差，把上下文解码从按键延迟中消掉。

# 一、用户说明

## 插件版还是源码版？

两版功能等效（同引擎同模型），**二选一**；切换 = 重装小狼毫 + 运行另一版安装器（方案配置自动转换，无需手动还原）。

| | 插件版（本仓库） | [源码版](https://github.com/zhanghaozhecn/rime-llm-ime) |
|------|------|------|
| 形态 | lua + DLL，跑在**官方小狼毫**上 | 源码级集成的整包（weasel + librime 改建） |
| 安装 | 需先装官方小狼毫，再跑安装器四按钮 | 单个 setup.exe，全新机器一键 |
| 光标上文 | COM + UIA + 历史（轮询快照） | TSF 光标采集 + COM（事件驱动，含导航键重采） |
| 适合 | 想保留官方小狼毫、动手最少 | 想要 TSF 级上文 / 全新机器最简安装 |

## 前置条件

- Windows 10 或更高（更早版本未验证）
- 小狼毫（Weasel）0.17.x 已安装，且 `rime.dll` 为官方原版（含 Lua 支持）
- 使用定长或不定长方案均可——哪些编码触发由 `编码匹配` 正则决定（默认恰 4 码 `.{4}`，四码定长方案如拼读双拼、五笔、郑码、仓颉开箱即用；不定长方案要改成 `.+` 等）；全拼/简拼等整句方案开启 `整句模式` 后编码匹配自动锁定为 `.{2,}`（2 码起参与重排）
- 磁盘约 600 MB：模型 `Qwen3-0.6B-Base-Q4_K_M.gguf`（397 MB，默认放 `%APPDATA%\Rime\`，RIME 用户文件夹；自定义位置用 `model_path` 指定，安装器可代下载）+ 插件数 MB

## 一键部署（推荐）

**插件版安装器**（本仓库 `installer\` 目录；源码版 2026-08-27 起改用 [rime-llm-ime](https://github.com/zhanghaozhecn/rime-llm-ime) 的 setup.exe 安装包，不再带 PS 安装器）。**单页界面**（2026-09-30 起与源码版设置界面同构），自上而下：**方案接入**（方案文件下拉）、**总控**（启用开关 + 模型路径下拉/浏览 + **下载模型** + 模型状态行）、**触发条件**（`编码匹配` 正则 + `整句模式` 复选框 + 仅整句模式勾选时出现的 `前缀自动确认` 复选框）、**推理规模**、**诊断日志**、**安装**（**复制文件** = 停算法服务 + 清理上次残留 → 二进制一律改名腾位 `*.llm_old` 替换 → 启服务），底部 **保存并生效 / 剥离 / 关闭**（**剥离** 就在保存右侧，是它的破坏性补充）。**下载模型**在模型路径那一行（ModelScope 直连断点续传，落点 = 该路径框，留空 = 默认 `%APPDATA%\Rime\Qwen3-0.6B-Base-Q4_K_M.gguf`；**下载完成后路径框自动填入实际落点**）。每个配置项一行、行末「?」悬停看说明；**界面不留日志框**——正常只看状态行，出错才写 `installer\install_error.log` 并弹框给出路径。**保存并生效是自适应的**：方案还没接入（缺配置节 / 缺组件行 / 残留另一版组件行）时会先剥净再补齐组件行 + 写入配置节（原「接入 LLM」按钮已并入这里），已接入则只重写配置节；无配置节的方案默认勾选「启用」，点一次保存即完成接入。参数读写选中方案的 `llm_rerank:` 节（与源码版同一套键），保存后自动重新部署。不碰注册表。

**方案下拉列出两处** `*.schema.yaml`：**用户文件夹** `%APPDATA%\Rime`（可写、Rime 优先）与**程序文件夹** `<小狼毫安装目录>\data`（预装方案 luna_pinyin / cangjie5 / bopomofo …，带「（程序）」后缀）；**打开下拉即重扫两处**（外部新增/删除方案后无需手动刷新），界面没有未保存改动时还会重读当前文件。预装方案**写入前会自动复制到用户文件夹**（写程序文件夹既要管理员、又会被下次升级覆盖；用户文件夹优先也正是 Rime 自己的解析顺序），程序文件夹里的原件不受影响。若方案文件在界面读入后被外部改过，保存前会弹一次确认，避免用陈旧界面值覆盖。

**前提**：已安装官方小狼毫。方案组件行**无需预先准备**——第 6 步「保存并生效」会自动幂等插入（`processors` 最前 `lua_processor@*llm_processor`、`filters` 的 `uniquifier` 后 `lua_filter@*llm_filter`、顶层 `llm_rerank:` 节）；手动添加参照"手动安装"第三步。

1. `git clone` 本仓库到目标电脑（或下载仓库 zip 解压——插件版文件在 `user\`，已入库）
2. **双击 `installer\install_plugin.bat`**（自动请求管理员权限；SmartScreen 弹"Windows 已保护你的电脑"时选"更多信息 → 仍要运行"——安装器未做代码签名）
3. 选择方案文件（下拉列出**两处**：用户文件夹 `%APPDATA%\Rime\*.schema.yaml` 与程序文件夹 `<小狼毫目录>\data` 的预装方案，后者带「（程序）」后缀——选预装方案时写入前会自动复制到用户文件夹）；模型路径留空 = 默认
4. 缺模型时点**总控**里的 **下载模型**：从 ModelScope 下载到模型路径（约 397 MB，断点续传——中断/失败后重新点击自动续传；完成后路径框自动填入实际落点）
5. 点击 **复制文件**：停算法服务 → `rime_llm.dll` 等 → 小狼毫安装目录；`llm_filter.lua` / `llm_processor.lua` → `%APPDATA%\Rime\lua\` → 启服务
6. 点 **保存并生效**：方案还没接入时它会自动补齐（幂等插入组件行：`processors` 最前 `lua_processor@*llm_processor`、`filters` 的 `uniquifier` 后 `lua_filter@*llm_filter`、顶层 `llm_rerank:` 节全键生效行）→ 自动重新部署（**剥离** 就在它右侧 = 逆操作；重复保存保留方案里已有参数与 `model_path`，不会被重置回默认）
7. 在**同一页**改 β / 词长权重 / 编码匹配等 → **保存并生效**（自动重新部署）；状态行有校验提示，非法输入不落盘
8. 验证：**先上屏一个词**（光标前无文字时不重排——刚装好打的第一个词必然保持原序），再打满 4 码观察候选顺序按上下文变化；记录 `%APPDATA%\Rime\llm_rerank\<方案>\rime_llm_corpus.tsv`（常开语料：上文/引擎序/最终序/提交词，事件 ID 可关联同目录 `rime_llm_debug.txt`；**LLM 数据/日志按方案分文件夹**（2026-11-22），语料/日志/账本/词码对都在 `llm_rerank\<方案 ID>\`）；逐候选分数用 [实时调试窗口](#实时调试窗口) 看（未生效时托盘小狼毫 → 右键 → 重新部署）

**切换版本**（插件版 ↔ 源码版）：重装官方小狼毫（恢复官方二进制）→ 源码版跑 [rime-llm-ime](https://github.com/zhanghaozhecn/rime-llm-ime) 的安装包 / 插件版跑本仓库安装器（其**保存并生效**会先剥离另一版组件行再插入，跨版自动转换，无需恢复原始方案配置）。

**输入法图标消失时**：运行源码版安装目录下的 `repair_tsf.ps1`（随 [rime-llm-ime](https://github.com/zhanghaozhecn/rime-llm-ime) 安装包装入，右键"使用 PowerShell 运行"自动提权重注册 TSF——插件版安装不碰注册表，此症状只源于源码版操作或系统问题）。

命令行模式：`install_plugin.ps1 -CliAction install|copy-files|schema-add|schema-remove|download-model|status -SchemaName pdsp.schema.yaml -ModelPath <模型路径>`（源码版同；`install` = 复制文件 + 配置加 LLM 全流程）。

## 手动安装

### 第一步：下载模型

打开 https://www.modelscope.cn/models/zhanghaozhecn/Qwen3-0.6B-Base-GGUF ，下载 `Qwen3-0.6B-Base-Q4_K_M.gguf`（约 397 MB），放到 `%APPDATA%\Rime\`（默认路径 = RIME 用户文件夹根；放其他位置需在方案中设置 `llm_rerank.model_path`）。安装器『下载模型』自动落盘为默认名。

> 放其他路径需在 schema 中设置 `llm_rerank.model_path`；**必须是绝对路径**（`D:\gguf_models\...` 或 UNC），
> 相对路径会被 GUI 拒绝保存（运行期把值原样交给 llama，相对值按服务进程的当前目录解析，必然加载失败）。

**模型路径的几条用户规则**（GUI 侧，两版一致）：

| 情形 | 行为 |
|------|------|
| 方案节里没写 `model_path` | 界面上直接显示**默认全路径** = Rime 用户目录（`RIME_LLM_USER_DIR` → 注册表 `RimeUserDir` → `%APPDATA%\Rime`）下的 `Qwen3-0.6B-Base-Q4_K_M.gguf`；保存时写注释占位（换机/便携部署自动跟新目录）|
| 指到的文件 >100MB | 状态行"模型已就绪：N MB" |
| 指到的文件 <100MB | 状态行"模型可疑：仅 N MB"（半截模型会让重排静默失效，不再谎报已就绪）；此时点『下载模型』会先确认再删除重下 |
| 手输相对路径 | 保存被拒绝，状态行提示"必须是绝对路径…"（文件不动）|
| 下载中断/关窗 | 分片 `<目标>.download` 保留，重开再点『下载模型』即续传；每次下载记 `<分片>.pid`，新下载会先结束上次遗留的 curl 进程 |

### 第二步：复制插件

**CPU（所有机器可用，零依赖）：** 将 `user\rime_llm.dll` 复制到小狼毫安装目录（需管理员）：

```
user\rime_llm.dll  →  C:\Program Files\Rime\weasel-0.17.4\
```

> GPU 版（rime_llm_cuda）因实用性问题仅本地留存，不发布。

### 第三步：配置 RIME

1. 将 `user\` 下两个 `.lua` 文件复制到方案 `lua\` 目录（即 `%APPDATA%\Rime\lua\`）
2. 在 `schema.yaml` 中添加：

```yaml
engine:
  processors:
    - lua_processor@*llm_processor
  filters:
    - lua_filter@*llm_filter
```

3. 右键小狼毫 → **重新部署**

上文来源三层自动判定（跨应用/跨窗口切换自动重置，无需配置）：`COM`（WPS 文字/演示的文档真文，经 COM 文档模型读取——含打开旧文档的既有内容）、`UIA`（记事本/浏览器/VSCode 等现代应用的 UIA TextPattern 光标前文）、`历史`（本会话上屏记录兜底）——当前来源与完整上文内容在[实时调试窗口](#实时调试窗口)实时可见（2026-11-10 起首选候选不再附加 `AI·` 来源徽章，候选窗保持干净）。**上文为空时不重排**（刚切到某应用/新开文档、还没上屏任何词）——此时候选保持原顺序，上屏第一个词后即恢复。**鼠标点击即视为光标可能移动**——任何点击自动重置兜底历史上文（不做例外排除，上下文宁短不错）；编辑键（退格/导航/回车/撤销/重做/粘贴/剪切）与点击同时使 COM/UIA 快照失效并触发 ~50ms 延迟重读——快照制的编辑事件盲区修复，旧快照不再在 2.5s 新鲜窗内冒充真文，打首词（人手 >300ms）时新快照已就绪。常开语料（W 行：`编码/上文/引擎原序/评分窗/最终序/状态`，C 行提交、M 行 reset；debug 明细另文件按事件 ID 关联）。**2026-11-22 起四个记录文件按方案分文件夹**：`llm_rerank\<方案 ID>\` 下各自一份（语料/日志/词频账本/词码对），不同方案互不混合；账本/词码对该方案首次使用时自动从旧位置复制快照（旧文件保留），切换方案后各方案独立演进。

```powershell
# 按方案查看（把 <方案> 换成当前方案 ID，如 pdsp / luna_pinyin）
Get-Content "$env:APPDATA\Rime\llm_rerank\<方案>\rime_llm_corpus.tsv" -Tail 5
```

> WPS 表格单元格编辑态为 COM 盲区（Office 系通病：编辑态对象模型不可见），落 UIA/历史兜底——已知边界。完整实验记录见源码版仓库研究文档（wps-context-investigation.md 十一~二十节，含统一标签页防串档四轮定案）。

## 配置参数

在方案的 `schema.yaml` 中配置（全部可选；也可在安装器**「方案接入」+ 参数区**（单页）图形化修改——写回选中方案的这一节，保存后自动重新部署）：

> 「最少上文 token」（`min_tokens`）自 2026-09-30 起**不再是用户配置项**：前期研究与长期实机使用确认它恒为 1（有上文即参与重排），
> 代码内默认值保留，方案里若残留旧行在保存 / 重跑重建节时自动剥除。
>
> 编码触发条件自 2026-09-30 起由「最小编码长度 / 最大编码长度」改为**单个正则** `code_pattern`（全串匹配），
> 旧键同样是残留即剥除。二者语义等价写法：`min_code_len: 4` + `max_code_len: 0` ⇒ `code_pattern: '.{4}'`。
>
> 正则风格提示：模式按 **Rime 自身 `auto_select_pattern`** 的写法（boost/std::regex ECMAScript 子集）。
> `\d`、`\w`、`\s` 等转义可用；含 `\` 的模式请写成**单引号**（`'\d{4}'`），双引号在 YAML 里会触发非法转义报错。

```yaml
llm_rerank:
  code_pattern: '.{4}'  # 编码匹配（正则，全串）；仅 4 码。4 码以上 .{4,}｜3-4 码 .{3,4}｜指定字母 [abcde]{4}｜留空 = 不限。整句模式开启时锁定为 '.{2,}'
  max_tokens: 20       # 截取的上文 token 数（2026-11-19 随生产模型切 Qwen3-0.6B base 定案）
  max_candidates: 6    # 并行评分候选数（2026-11-19 随生产模型切 Qwen3-0.6B base 定案）
  # sentence_mode: false # 整句模式：等长词与子词统一进评分窗（层1 取前 k、全部真算 CE），显示统一概率序；组句不参与评分、只置顶 ngram 序首选 1 条。编码匹配锁定 '.{2,}'（2026-11-24 统一准入 + phrase-only）
  # prefix_confirm: false # 前缀自动确认：组句 lead 概率 ≥0.95 且该文本是窗口融合序第 1 → 自动选入组合区（不上屏）；剩余 ≥2 音节（单音节 lead 例外，≥1）；只在 sentence_mode 开启时显示/生效（2026-11-24 合并单一路线 + 音节守卫）
```

### 词频与词长融合公式

内置常数 `β=14`（词频权重；2026-11-14 随默认模型 0.5B 重标定，旧 β=12 为 0.8B v3 值）按统一结合公式在**对数域三项相加**，命中词码对分数修正的再加减一个 delta（正分 +200/+100 固定首选/次选、负分 −5 降噪；公式与参数语义见源码版 README「词频与词长融合公式」节，两版逐字一致；用户 bigram 项已于 2026-11-08 退役——cohort 生产量级评测实证其在真实用户龄几乎无贡献，历史结论见研究资料库）：

```
fused(w) = score(w) + β · log(1 + eff(w)) + log( uni(w) + 1 ) + delta(w)
```

（2026-11-11 起累计项简化为 `log1p(uni)`——原 `log p1` 的分母/δ 均为窗内常数、排序不变量，位级等价去除。）

- `score(w)` = 原始 LLM 分，即候选词在上文条件下的负交叉熵（−CE，对数概率域，越大越好）
- `eff(w)` = Rime 同源的时间衰减计数（librime `algo::formula_d`，与引擎调频 userdb 同一公式）：

```
提交（每次含中文上屏，全局 tick ← tick + 1）:   dee ← 1 + dee · exp((t_w − t) / τ)
查询（打分时刻）:                               eff = dee · exp((t_w − t) / τ)
τ = 400 tick，半衰期 ≈ 277 次提交（v3 2026-11-06 六维联合标定：用户域标定 → wiki 平台内就近点；旧值 800 出自 2026-11-02）
```

- `dee` = 该词的衰减计数，`t_w` = 该词最后提交的 tick，`t` = 当前全局 tick。近期常打的词 eff 高，久未使用自动消退
- `uni(w)` = 用户累计 unigram 原始计数（与衰减计数同存 `user_ledger.tsv` 的 `cum` 列，见下条；只计含中文的词、原始计数不衰减；曾配套的用户 bigram 项已于 2026-11-08 退役）
- **词码对扣分修正（2026-11-21 解耦：只承载负分，两版一致）**：表在用户目录 `llm_pairfix.tsv`，行 `词<TAB>码<TAB>-分数`（无第三列 = 旧默认 -5）——对 CE 分数系统性偏差做降噪修正，**只在重排评分窗内生效、受 fade**（用户该词码对累计 ≥3 次 → 让位）；2026-11-17 的 +200 固定首选/+100 固定次选正分语义废除（正分行读取端跳过）。`#` 注释；无文件 = 休眠。`debug_fusion` 开启时 debug 的 D 行 `sdelta=-5/0`（v6 C 行尾追加 `sdelta`，旧 `pf` 字段保留兼容）；调试窗**无修正分专属列**（2026-11-21 v7：命中修正折进 CE 格数值并在公式右侧追修正项，未命中不显示）。**固定候选已解耦为拼读双拼本机功能**：`pin_candidates.tsv`（编码首列 + 位次列）+ `pin_filter.lua` 全局重排（LLM 开关无关、固定优先于重排、固定词 comment 追加 📌），0/9/8/7/6 键写入/解除——与 LLM 重排零耦合。
- **整句模式**（`sentence_mode`，默认关闭）：**层1 词频在等长词+子词里统一取前 k 进评分窗、全部真算 CE**（2026-11-24 用户定案，取代 2026-11-22「满覆盖优先占满窗」——等长 ≠ 概率高）；显示统一概率序（[组句首选 1 条] + 窗口融合序 + 窗外层1 序，三块与子词复用分退役）；**组句不参与评分**（phrase-only 2026-11-24 定案），只置顶 ngram 序首选 1 条（top-20 的分数供前缀确认的 lead 概率，不再做全句 CE）。**开启后编码匹配锁定 `.{2,}`**（运行期忽略方案节 code_pattern）。两码一字方案与旧「词长==⌊码长/2⌋」逐位等价（2026-11-22 泛化；2026-11-24 统一）
- 词频由上屏自动统计（RIME 用户目录 `llm_rerank` 子目录的 `user_ledger.tsv`，两版共用，每 20 词落盘；**2026-11-21 起 LLM 数据/日志收进该子目录**；**2026-11-17 起衰减账 + 累计账合并单文件**：首行 `#tick=N`，随后 `#` 列含义注释行（落盘自带），数据行 `词\t码\tdee\ttick\tcum`（码可空；**2026-11-20 去掉行类型列 s**，读取端兼容旧 6 列 s 行）；`dee/tick` 记含中文上屏的衰减计数，`cum` 只对含中文词条累计。旧 `user_eff.tsv`（回退 `user_freq.tsv`）与 `user_unigram.tsv`（回退 `user_bigram.tsv`）由读取端一次性合并迁移、旧文件保留不删；`n_seen` 不再记录）

**词码对修正无专属列**（2026-11-21 v7，取代旧「修正分」列）：命中时折进 CE 格数值并在公式右侧追修正项（如 `-19.5 = -(14.5) - 5.0`），未命中不显示；验算 `总分 = CE格(含修正) + 衰减词频分 + 累计词频分`。

（`窗`、`匹配词长`、`修正分` 列已删：前两者 2026-11-16 定案——尾窗透传行仍以**灰字**区分（未进 LLM 评分）、满长准入优先下**有无 CE 分即满长标志**；修正分 2026-11-21 定案——恒 0 的独立列无观察价值，折进 CE 格。）

## 线程数实测

CPU 线程数随机器而变（默认 4 只是 GGML 默认），测一次能拿到本机最优值：**安装器 →「推理规模」→ CPU 线程数右边的『实测线程数』**，加载本机模型实测 4~8 线程的 **t_cand**（候选段延迟：当前「候选数」个 3-token 候选的两次 decode，预填充不计），约 30 秒后弹框给出逐档延迟表 + 推荐值，点「是」把推荐值填进输入框，再点『保存并生效』应用（自动重新部署）。

- **延迟口径 = t_cand**：候选段两次 decode（k 个 3-token 候选、首 token 互不相同 = 前缀去重失效的最坏情况），ctx 预填充不计（生产里它在 commit 后异步完成）；**k 跟界面上「候选数」当前值走**，实测与即将保存的推理规模一致
- **推荐口径**：取最优延迟 × 1.05 以内**最快**（线程数最小）的档位，且不超过本机物理核——超出物理核的线程是 SMT 兄弟线程，对这个负载几乎不涨分
- **本机不足 5 逻辑核不做实测**，直接取最大线程数（省得在低核机上白等 30 秒）
- **建议系统空闲时实测**（有编译/下载/游戏在跑会压平曲线、延迟失真），实测期间也请勿打字
- 关掉界面会一并结束实测进程；异常退出（强杀）留下的进程，下次点『实测线程数』会自动接管

也可以在命令行单独跑同一个工具（`bin/bench_threads.exe`）：

```
bin/bench_threads.exe [模型路径] [--cands K] [--out 结果文件] [--trials 每档次数] [--no-wait]
```

- `--cands` 候选数（默认 6，钳位 1~32；GUI 传输入框里的 `max_candidates`）
- `--trials` 默认 99（约 1 分钟，更稳）；GUI 用 41（约 30 秒）
- 末行 `[RESULT] ... rec=N rec_ms=... best=... cands=K reason=ok|low_cores` 是机器可读的推荐结果（两个设置界面都读它，所以推荐规则只有一份）
- 结果/进度写入 `--out` 指定文件（留空 = exe 同目录，不可写则 `%TEMP%`），逐行 flush 供界面轮询

不跑实测也可用默认值 4。自行编译源码：`cpp/build_bench_threads.bat`（需本机 llama.cpp 构建）。

## 常见问题

- **Q: 装了没效果？** 确认 ① schema 组件位置正确（filter 在 uniquifier 后、固顶 filter 前）② `enabled: true` ③ 重新部署过 ④ 模型路径存在 ⑤ **光标前有文字**（重排至少需 1 个上文 token——刚装好/空文档里打的第一个词必然保持原序，先上屏一个词再看）。确凿验证开 [实时调试窗口](#实时调试窗口)：能看到逐候选分数即已生效，看到"跳过"行则是没触发的具体原因。
- **Q: 候选变乱序/被顶掉？** 检查固顶词 filter（pin_fix_filter 等）是否在 `lua_filter@*llm_filter` **之后**——先固顶后重排，固顶词会被 LLM 顶掉。
- **Q: 每击键延迟明显？** 在安装器「推理规模」点『实测线程数』按推荐值设 `cpu_cores`（或跑 `bin/bench_threads.exe`）；确认 `max_tokens`/`max_candidates` 未调高；确认预解码生效（事件日志延迟应 ~36 ms 而非 ~80 ms）。
- **Q: 编辑器里插入的英文/数字算上文吗？** 算。上文中允许字母存在，仅去空白；外挂无法感知光标前完整文本，英文数字是合法上文（见代码注释）。
- **Q: 日志在哪？** `%APPDATA%\Rime\llm_rerank\rime_llm_corpus.tsv`（常开语料：W 推理窗/C 提交/M 重置，含上文与来源）；同目录 `rime_llm_debug.txt`（仅 `debug_fusion` 开启时写 CE/eff/耗时等明细，按事件 ID 与语料关联；错误行始终保留）。

# 二、研究主要结论

**方法**：对同码候选做 `argmax P(wᵢ | ctx)` 的交叉熵评分（只排序、不生成、编码无关、本地 CPU）。三项核心技术：

1. **分层并行解码**——所有候选共享同一段上文，上文只解码一次、首 token 同帧出分，N 候选 ≤ 3 次 `llama_decode`（朴素逐候选 274ms → 生产 43ms）。约束：每序列增量 1 token（Qwen3.5 的 SSM 跨序列干扰）。
2. **预解码 + KV 代次机制**——commit 后异步预解码上文，按键时只算候选部分（感知延迟减半）；代次计数保证复用的 KV 与 logits 一致（杜绝编辑流中旧预解码状态误用）。
3. **CE 位置权重**——前 3 token CE 按 (1.0, 1.10, 0.60) 加权求和（2026-11-14 随默认模型 0.5B 重标定；旧值 (1.0, 1.05, 0.45) 为 0.8B v3 值、(1.0, 1.13, 0.61) 出自 2026-09-16 前缀标定）；4+ 字候选只算前三项（尾部外推经 20k 样本端到端扫描证伪后删除：λ=0 全曲线最优）。

**实验结论**：

- 首选率 93.4%（历史口径，10 tok / 5 cand，20000 样本）；单字 96.8%；模型上限 ~94.3%。
- **延迟分两段计（2026-11-18 定案）**：**上文预填充** ≈3.8–6.2 ms/token（0.5B/0.6B/0.8B；
  2B 13.4），**候选段最坏情况**（全候选 3 token、首 token 互不相同）≈14–41 ms/候选。
  两段是独立预算：ctx 决定预填充量，候选数决定按键等待。实测 0.5B：prefill(ctx10)=76ms、
  候选段 k=2/5/9 = 44/102/172ms；**2B 两段都超预算**（prefill ctx14 已 228ms、
  候选段 k=2 已 140ms）→ 出局。**研究推荐（2026-11-19，尚未改生产默认）：ctx=20、
  Qwen3-0.6B base Q4_K_M + k=6（100ms / 3.28%）**；0.5B base k=6（102ms / 3.56%）
  为回退档，0.8B base k=4（91ms / 3.55%）仅作规模对照。三个 0.6B/0.8B/0.5B 均为
  official **base** 权重自建 Q4_K_M（旧“0.6B 出局”是对话微调版权重的结论，回 base 后
  0.6B 反而全线最优）；量化与版本比较见研究库 README「附录 A」。
- 模型规模（2026-11-14 两域同窗对照，历史）：**默认 0.6B base**（2026-11-19 定案，见上）；0.5B base 保留为回退档、0.8B 精度拐点可自选（`model_path` 指向即可，全兼容）；2B +0.33pp 但延迟 1.78× 不采纳。
- 词频对数融合 `β=14`（2026-11-14 随默认模型改 0.5B 重标定，kCeW (1.0,1.10,0.60)；旧 β=12/kCeW(1.05,0.45) 为 0.8B v3 值）内部常数（fused = LLM分 + β·log1p(eff) + log1p(uni)，eff 为 Rime 时间衰减计数；2026-11-02 连续文章语料重标定，5.9 万窗全程累计口径较纯 LLM +1.9pp；旧 β=1.5 出自独立窗口径仅 +1.0pp；2026-11-05 起退出配置面；2026-11-11 起公式简化为 log1p(uni)——原 log p1 的分母/δ 均为窗内常数、排序不变量，位级等价去除）。词频无上限可翻盘（凸组合时代词频结构性封顶 0.25）。
- GPU 版放弃（CUDA graph 重编译/省电波动/特定输入卡死）；模型能力上限 ~94.3%。

完整研究文档（方法细节、tok×cand 全量扫参表、词频融合研究）在本地研究资料库 `llm-rerank-research\`（与本仓库同级目录；评测工具链与语料同在其中）。

## 核心算法要点

分层并行解码、预解码、KV 代次、CE 位置权重的完整原理见研究资料库 README「方法」节；实现层的坑（索引语义、代次连锁失配、`llama_memory_clear` 参数、`llama_tokenize` 负返回、lua 缓存误命中、编辑键重置根因、候选窗快照动机等）已写入代码注释，改代码前先读 `cpp/rime_llm.cpp` 的 `score_batch`/`prepare` 与两个 lua 文件顶部的注释。

### 异步评分（2026-11-22 起，字词/整句两模式统一）

评分移出按键路径：filter 每键投递异步任务（指纹 = 上文+候选文本）。**字词模式** submit+wait（≤250ms）；**整句模式** 窗口 3-token submit + **短预算 wait（150ms）**，预算内完成即用融合序上屏，超时回填 `async_pending`（filter 入口 / commit 收割点）。**组句不进评分**（2026-11-24 phrase-only）：窗口只有 ≤max_candidates 个候选参评，组句只贡献 ngram 序首选与 lead 概率。同指纹重复 query 命中快照缓存。语料 W 行两种形态：正常 `ok`；超时挂账 `skip|async_pending` + 回填 `ok`（flags=`async`）。设计全文见研究库《全拼简拼整句重排-调研与设计》§七/§11.13。

**大词库方案（朙月拼音等）的候选收集限量**（2026-11-22 卡死修复）：候选收集
双重限制 = **16 上限 + 30ms 时间预算**（个数闸管收多少、预算闸管贵不贵）——
候选爆炸主因 = **连续声母简拼**（全拼串 completion 有限、简拼串海量），全量
收集曾致单码 0.5-2.25 秒 CPU（enabled=false 对照实测 40 倍差）→ server 消息
线程占死 → TSF 管道重连风暴 → 输入法与宿主应用全卡。上限 16 的依据 =
2026-11-23 真实引擎 wiki 全拼位置实测（15,925 词型）：正确候选位置 p95=2 /
p99=7 / p99.9=20；k=16 覆盖 99.82% 词型、99.92% 词频加权（k=32 边际仅
+0.16pp）。限量的语义代价：16 外深翻页候选不再出现、层1 词频选窗在已收集
范围内进行（实际影响可忽略）。

### N-gram 组句候选（2026-11-23 第②段，插件版能力子集）

`llm_rerank/ngram_group: true` 打开后，过滤器用**词级 N-gram beam** 生成
**top-20 整句候选**（2026-11-24：topk 5→20，供 lead 概率质量；显示仍只
1 条 = ngram 序第 1）。组句器在 `rime_llm.dll` 内（`cpp/ngram.cpp`）：万象
LTS `.gram`（Rime octagram 格式，44B 头 + Darts 双数组）+ 万象词库
（词→码→词频）做码串格 beam；`Octagram::Query` 逐项复刻。

- 生产参数：beam 32 / 每码位最多 8 条边 / 词频下限 10 / 上文尾部 10 字。
  实测 **14.6–15.5ms 每句**（14–30 码串），wiki A/B **hit@5 73% / 61%**
  （研究脚本 71% / 62%）；topk 20 实测 4.0→4.1ms/窗（beam 本就探索 32，
  只是输出截断不同）。与 `eval/tools/sentence_gen_gram.py` 留档
  **100/100 逐句一致**（文本+分数，误差 <1e-6）。对拍工具：
  `cpp/ngram_parity.lua` + 研究库 `eval/tools/ngram_parity_check.py`。
- 词表索引：首次解析万象 dicts → 二进制 mmap 缓存（约 86MB/方案），
  二次加载近 0 秒；缓存路径 `llm_rerank\ngram_lex\<方案>.bin`。
- **插件版边界**：官方 rime.dll / TSF 没有推送通道、异步指纹随输入变化，
  所以插件版只有「组句 top-20 + 3-token 窗口融合序 + 合并前缀确认」；
  **无按键刷新是源码版专有**（插件版在 processor 下一键执行确认，见源码版
  README）。
- **合并前缀确认（2026-11-24 定案，取代 5 条 lead 投票 + θ）**：组句侧
  `P(lead) = Σ exp(score−max) / Σ exp(score−max)`（按 lead 分组）≥ 0.95，
  且该文本必须是窗口融合序第 1 且 span 对齐 → 挂起。同精度下召回比
  「5 条 lead 全一致」高 51%（95.56% 精度 / 34.43% 召回 / K=5 +2,001）；
  阈值 0.90 落进双峰低谷（P∈[0.90,0.97) 精度仅 81.9%）。误确认只发生在
  组合区内（不上屏），可见可退格撤销。

## 调试接口

- **常开语料**：`rime_llm_corpus.tsv`——`W`（每次满码尝试：编码/上文/引擎原序/评分窗/最终序/状态）、`C`（提交词/码/名次）、`M`（reset 场景边界）；`H` 为进程配置。**debug**：`rime_llm_debug.txt` 只写 P（耗时）/D（逐候选 CE/eff/频+/u1+/key/修正）/E（commit eff 前后）/R（reset 代次）/X（错误），用 W/C/M 事件 ID 关联；错误 X 始终写。
- **`get_scores()`**：C++ 插件在 `score()` 后保存原始分数，`llm.get_scores()` 返回 `{[候选词]=分数}` 的 Lua 表，仅用于调试分析（lua filter 层不消费）。

```lua
local ranked = llm.score(ctx, cands)     -- 排序表（正常使用）
local scores = llm.get_scores()          -- 数值分数（调试用）
```

- **`test_core.exe`**：CE 正确性（分层 vs gold 对比）+ 准确率/延迟回归基线（`test_baseline.json`），改评分逻辑后必跑。

## 安装器原理

`installer\install_plugin.ps1`（**单文件全部逻辑**；`install_plugin.bat` 为 ASCII 提权垫片——**优先 pwsh 7、回退系统自带 PowerShell 5.1**（.ps1 带 UTF-8 BOM，5.1 也能正确解析中文；无 BOM 时 5.1 按 ANSI 解码会在解析期就报错 = 双击闪退，2026-09-30 修）。2026-09-04 起原入口壳 + common.ps1 双文件合并：源码版 2026-08-27 改 setup.exe 分发后"两仓共用"已名存实亡，源码版动作与双版分支一并删除）。GUI 为**单页**（2026-09-30 起；与源码版 WeaselLLMSetup 同构）：方案接入（方案下拉）+ 总控（启用 / 模型路径 / 下载模型 / 模型状态）+ 触发条件（编码匹配 + 整句模式 + 前缀自动确认——后者仅整句模式勾选时显示）+ 推理规模 + 诊断日志 + 安装（`复制文件`）+ 保存并生效 / 剥离 / 关闭（下载模型在总控的模型路径行）；**无日志框**，出错写 `installer\install_error.log`。`复制文件` / `下载模型` / `剥离` 各起一个 CLI 子进程——`copy-files`（停服务 + 清残留 → 二进制一律改名腾位 `*.llm_old`，复制失败回滚 → 启服务）、`download-model`（curl.exe 断点续传 ModelScope → `.download` 分片 → 完成转正；子进程输出轮询取末行做进度反馈）、`schema-add`（**先剥离后插入**——方案原状无论无 LLM / 本版 / 另一版组件均先剥净再全新插入，跨版自动转换；`model_path` 与已有参数逐键保留——`Read-LlmParams` 先读后剥、`Get-LlmCfgLines` 重建节时回填，重跑不重置用户自定义）、`schema-remove`（剥离两版组件行与 `llm_rerank` 节）；配置类动作完成后自动重新部署（15 秒有界等待，超时留后台）。参数读写为进程内轻量操作，不走子进程：`Read-LlmParams` 解析选中方案 `llm_rerank:` 节（缺键回 lua 默认）→ 控件回填；`Update-LlmSection` 原位重写节（组件行不动），保存后 `Invoke-Redeploy`。不碰注册表、不调 WeaselSetup。所有 schema 读写为 UTF-8 无 BOM。GUI/CLI 自动化测试：`installer\test_gui.ps1`（APPDATA 沙箱隔离 + `LLM_INSTALLER_NO_REDEPLOY` 钩子，pwsh 7 运行；复选框断言走 BM_CLICK + 落盘——WinForms 主题复选框的 BM_GETCHECK 跨进程读不到内部态；G9 断言"正常不写、出错才写 install_error.log"）。
